# MouseVPN Roadmap

MouseVPN — экспериментальный VPN с собственным wire-протоколом, общим ядром на
Rust и платформенными оболочками для Linux и Android.

> Собственный протокол не означает собственную криптографию. Для обмена ключами,
> шифрования и аутентификации используются только проверенные примитивы и
> библиотеки. Невозможно гарантировать, что протокол никогда не будет
> заблокирован; цель проекта — безопасность, заменяемые транспорты и отсутствие
> стабильного лишнего сетевого отпечатка.

## Цели MVP

- один Linux-сервер и один Linux-клиент;
- весь IPv4-трафик клиента проходит через TUN и серверный NAT;
- DNS не утекает мимо туннеля;
- сервер аутентифицируется, пакеты шифруются и защищаются от повторов;
- при потере соединения kill switch не выпускает трафик напрямую;
- сетевое ядро не зависит от Linux API и пригодно для вызова из Android;
- установка и удаление сетевых правил обратимы даже после аварийного завершения.

## Архитектурные границы

```text
crates/protocol       wire format, parsing, packet numbers, errors
crates/crypto         handshake, keys, AEAD, replay window
crates/transport      transport traits; UDP implementation first
crates/client-core    platform-independent tunnel session
crates/linux-client   TUN, routes, DNS and kill switch on Linux
crates/server         session handling and packet forwarding
crates/android-native Android JNI adapter and TUN packet loop
crates/profile-cli    encrypted MV1 portable-profile generator
crates/device-cli     one-key-per-device provisioning utility
android/app           Kotlin UI + VpnService; Rust core through JNI
```

Платформенный код владеет TUN и жизненным циклом приложения. `client-core`
получает и отдаёт IP-пакеты через небольшие интерфейсы и не обращается напрямую
к `/dev/net/tun`, `ip`, nftables, Android SDK или JNI.

- [x] Rust workspace и границы компонентов.
- [x] Версионируемый заголовок пакета с безопасным декодированием.
- [x] Заготовки Linux-клиента, сервера и Android integration notes.
- [x] Установить стабильный Rust toolchain.
- [ ] Включить CI.
- [x] Зафиксировать threat model и свойства безопасности.

## Этап 1 — защищённая сессия без TUN

- [x] Аутентифицированный Noise IK handshake на X25519 + SHA-256.
- [x] ChaCha20-Poly1305 для пакетов данных через Noise transport mode.
- [ ] Уникальные nonce, раздельные ключи направлений и ротация ключей.
- [x] Скользящее окно защиты от replay.
- [x] UDP-транспорт, зашифрованный keepalive, watchdog и повторный
  handshake без снятия kill switch; миграция между сетями ещё
  предстоит.
- [x] Loopback UDP handshake и encrypted echo для трёх клиентов.
- [ ] Golden vectors, fuzzing декодера и тесты повреждённых пакетов.

Критерий готовности: две стороны создают сессию, передают произвольные данные,
отклоняют подменённые и повторные пакеты, не паникуют на случайном вводе.

## Этап 2 — Linux MVP

- [x] Linux TUN adapter без shell-команд.
- [x] Подключить TUN adapter к долгоживущему client/server event loop.
- [x] Сохранение маршрута до VPN-сервера вне туннеля.
- [x] Маршрут по умолчанию через TUN.
- [ ] Серверный forwarding и nftables NAT.
- [x] Подготовлен reviewable draft nftables NAT/forwarding policy.
- [x] Link-specific DNS через `systemd-resolved` внутри туннеля
  с rollback при завершении; другие resolver backend ещё не поддержаны.
- [x] Kill switch и rollback маршрутов/nftables при `Ctrl+C` и
  фатальной ошибке; после `SIGKILL` нужна recovery-команда.
- [ ] Обработка MTU, ICMP Packet Too Big и фрагментации.
- [ ] systemd units и минимальная конфигурация TOML.

Критерий готовности: браузер, CLI и фоновые приложения используют внешний IP
сервера; при отключении кабеля, падении процесса и перезапуске DNS/IP не утекают.

## Этап 3 — эксплуатационная безопасность

- [x] Взаимная аутентификация устройств и in-memory API отзыва ключей.
- [ ] Зашифрованное постоянное хранилище пользователей и ключей.
- [x] Базовый rate limit handshake и увеличенные UDP-буферы для нескольких клиентов.
- [ ] Защита handshake от amplification и простого DoS.
- [ ] Секреты не попадают в логи и core dumps.
- [ ] Наблюдаемость без записи адресов посещённых ресурсов.
- [ ] Независимый аудит протокола перед реальным использованием.

## Этап 4 — Android

- [x] Kotlin-приложение с `VpnService` и foreground notification.
- [x] Менеджер нескольких именованных серверов с разными ключами.
- [x] Отдельная выдача ключей и IPv4-адреса каждому устройству.
- [x] Зашифрованный переносимый профиль `MV1.…` с копированием и вставкой.
- [x] Передача TUN file descriptor в Rust через узкий JNI API.
- [x] Сборка протокольного Rust-ядра для `arm64-v8a` и `x86_64`.
- [x] Повторный handshake Android на том же защищённом сокете после потери сессии.
- [ ] Немедленная реакция на смену Wi-Fi/mobile network и отдельные тесты Doze mode.
- [ ] Always-on VPN, блокировка соединений без VPN и split tunneling.
- [x] Защищённое хранение ключей через Android Keystore.
- [ ] Инструментальные тесты утечек IPv4, IPv6 и DNS.

Критерий готовности: один и тот же протокол и session core работают на Linux и
Android; платформенные различия остаются в Kotlin/JNI слое.

## Этап 5 — сменные транспорты

- [ ] Стабильный trait транспорта, не связанный с handshake.
- [ ] TCP/TLS-like или другой резервный транспорт после измерений.
- [ ] Миграция сессии между сетями и адресами.
- [ ] Конфигурация нескольких серверов и безопасная ротация endpoint'ов.
- [ ] Измерение распознаваемости и производительности каждого транспорта.

Транспортная вариативность повышает живучесть, но не даёт обещания
«неблокируемости»: IP-адрес, активное зондирование и статистическое поведение
соединения всё равно могут использоваться для ограничения доступа.

## Производительность

До оптимизации фиксируем baseline и измеряем:

- throughput, p50/p95 latency и CPU на ядро;
- количество копирований каждого IP-пакета;
- syscalls и размер UDP batch;
- влияние MTU и размера AEAD record;
- расход батареи на Android.

Оптимизации после профилирования: пакетная обработка (`sendmmsg`/`recvmmsg`),
пулы буферов, уменьшение аллокаций и многопоточная обработка независимых
сессий. `unsafe` не добавляется без измеримого выигрыша и отдельного аудита.

Первый локальный crypto-only baseline (release, 100 000 пакетов по 1200 байт,
encrypt + decrypt с текущими аллокациями): около 2.15 Гбит/с. Это не end-to-end
скорость VPN; результат нужен для сравнения последующих изменений на той же
машине.

## Не входит в первый MVP

- GUI, аккаунты, платежи и панель администратора;
- iOS, Windows и macOS;
- mesh/multi-hop;
- обещания анонимности или обхода любой блокировки;
- собственные шифры или неподтверждённые криптографические конструкции.
