# Speedy v1

Статус: первая экспериментальная реализация для Linux-клиента и сервера.
Legacy остаётся режимом по умолчанию и сохраняет прежний wire-формат, ключи,
Noise-контекст и MTU. Android, Windows и Apple GUI продолжают предлагать
прежние режимы. Сервер принимает Legacy, MouseMorph и Speedy на одном UDP-порту.

## Назначение

Speedy добавляет минимальную маскировку к одному слою шифрования данных Noise.
Он скрывает открытый заголовок MouseVPN, включая тип, ID сессии и счётчик,
и проверяет целостность всего внешнего кадра. Нет повторного шифрования всей
нагрузки, случайного padding, cover traffic и задержек перед handshake.
Буферы, пакетная обработка UDP, keepalive и восстановление Linux-клиента
используют существующий сетевой код.

Это режим для небольших накладных расходов с минимальной маскировкой.
Legacy требует меньше вычислений. Speedy не обещает скорость или RTT прямого
соединения: маршрут до сервера, CPU, очереди, MTU и потери остаются существенными.

## Криптографические границы

Шифрование, аутентификация клиента и сервера, forward secrecy и защита от
повторов обеспечиваются `Noise_IK_25519_ChaChaPoly_SHA256` и существующим
окном на 8192 номера. Внутренний формат туннельных пакетов не меняется.
Счётчики остаются 64-битными; переполнение завершает передачу до повторения nonce.

Speedy использует отдельный Noise prologue:

```text
SHA-256("MouseVPN Speedy v1 context\0" || server_static_public_key)
```

Это исключает перенос Speedy-handshake в Legacy/Morph и автоматическое
понижение режима. Клиент, выбравший Speedy, не переключается на Legacy после
тайм-аута. Старый сервер не поддерживает Speedy, пока не обновлён.

Ключ маскировки получается через X25519 и HKDF-SHA256:

```text
shared = X25519(local_private_key, peer_public_key)
master = HKDF-SHA256(
    salt = "MouseVPN Speedy v1 key",
    ikm = shared,
    info = server_public_key || client_public_key,
    length = 32)
```

Нулевой shared secret запрещён. Из master как PRK выводятся независимые
32-байтные ключи маршрутизации, маски и MAC для каждого направления:
HKDF-Expand-SHA256 с info `53 50 01 direction purpose`, где direction равен
0 для client→server и 1 для server→client, purpose равен 0/1/2 соответственно.

Покрытие заголовка использует подход «PRF от образца шифротекста», описанный в
[RFC 9001 §5.4](https://www.rfc-editor.org/rfc/rfc9001.html#section-5.4).
Speedy применяет собственное кадрирование и не является QUIC.
[Keyed BLAKE3](https://docs.rs/blake3/latest/blake3/fn.keyed_hash.html) используется
как готовая PRF/MAC; новые криптографические примитивы не вводятся.

## Формат UDP-кадра

| Поле | Размер |
| --- | ---: |
| Меняющийся маршрутный тег | 8 байт |
| Замаскированный заголовок MouseVPN | 20 байт |
| Исходное сообщение Noise, включая его тег | переменный |
| Внешний MAC | 16 байт |

Открытой фиксированной сигнатуры Speedy или номера версии нет. Версия
закреплена в контексте и ключах. Все целые числа в заголовке — big endian.

Для эпохи `floor(unix_seconds / 10)` маршрутный тег равен первым восьми байтам
HMAC-SHA256(route_key, `"Speedy v1 route\0" || epoch_be_u64`). Принимаются
текущая и две соседние эпохи. Ключи и теги кэшируются; сервер ищет устройство
по хеш-таблице и отбрасывает неоднозначные теги, включая коллизии с Morph.

Маска заголовка — первые 20 байт keyed BLAKE3(mask_key,
`routing_tag || last_16_bytes_of_Noise_message`). Образец всегда берётся из
тега Noise, включая handshake; открытый ephemeral key не используется.
Маска накладывается XOR на все 20 байт заголовка.

Внешний MAC — первые 16 байт keyed BLAKE3(auth_key,
`routing_tag || masked_header || Noise_message`). Он проверяется сравнением
с постоянным временем **до раскрытия заголовка**. Изменения любого байта кадра
отбрасываются. После снятия маски обязательны обычные проверки Noise и replay;
внешний MAC не заменяет их. Сам codec не хранит окно повторов.

Нулевые flags обязательны. Handshake разрешён только в своём направлении с
нулевым sequence. Неизвестные виды пакетов и Close пока отклоняются.
Повторная отправка того же handshake в той же эпохе даёт тот же кадр; сервер
возвращает прежний Noise response, сохраняя уже созданную сессию.

## MTU и накладные расходы

| Режим | Байты сверх IP-пакета, без внешних IP/UDP |
| --- | ---: |
| Legacy | 37 |
| Speedy | 61 |
| MouseMorph v2 | 79–110 |

Speedy добавляет ровно 24 байта к Legacy. Максимальный UDP payload — 1452 байта.
MTU туннеля ограничен `min(server_configured_mtu, 1391)`; это помещается в
1500-байтный путь как с внешним IPv4, так и с IPv6. Для пути меньшего размера
нужно дополнительно уменьшить серверный MTU. PMTU discovery и фрагментация
в эту версию не входят. На MTU других режимов Speedy не влияет.

## Использование и проверка

После сборки обновлённого сервера и Linux-клиента выберите **Speedy** в списке
протоколов отключённого профиля. Ключи и импортированный профиль подходят прежние.
Для CLI добавьте в клиентский TOML:

```toml
protocol = "speedy"
```

История стабильности Linux GUI хранит Speedy как отдельный режим. 11 сентября
2026 по запросу владельца обновлены три сервера; результаты прямых сетевых
проверок описаны в [отчёте об обновлении](SPEEDY_ROLLOUT_2026-09-11.md).

Для проверки настоящих IP-пакетов без изменения локального TUN, маршрутов и DNS
есть диагностический пример. Нужен отдельный временный профиль: handshake
заменяет предыдущую сессию того же устройства. После проверки ключ надо отозвать.

```sh
cargo run --release -p mousevpn-linux-client --example packet_probe -- /path/to/disposable.toml speedy 1.1.1.1
```

Он проверяет ICMP Echo для IP-пакетов размером 64 байта и согласованным MTU,
по 10 ответов каждого размера. Это проверка связности, а не тест пропускной
способности. Для пакета установлен IPv4-флаг Don't Fragment.

Локальное сравнение полного пути encode→decode при одинаковых размерах IP:

```sh
cargo run --release -p mousevpn-speedy --example packet_path
```

Измерение включает Noise, replay, оболочку и переиспользуемые буферы; не включает
TUN, UDP, конкуренцию потоков и интернет. Для реальной скорости и устойчивости
нужен стенд по [PERFORMANCE_TESTING.md](PERFORMANCE_TESTING.md): сравнить
прямое соединение, Legacy и Speedy в обе стороны, при одинаковой нагрузке.

Локальный замер 11 сентября 2026: Intel Core i5-8600K, Linux x86-64,
Rust 1.98.1, release/thin LTO. Медианы пяти запусков, по 100 000 пакетов
каждого размера и 1000 прогревочных итераций. Во время итоговых запусков
параллельные сборки проекта не выполнялись.

| Размер IP-пакета | Legacy, нс | Speedy, нс | Morph Balanced, нс |
| ---: | ---: | ---: | ---: |
| 64 | 360 | 813 | 5644 |
| 512 | 801 | 1982 | 6730 |
| 1280 | 1535 | 4081 | 8638 |

Для 1280 байт Speedy сокращает время обработки относительно Morph Balanced
примерно на 53%, но остаётся дороже Legacy на 2,55 мкс за encode+decode.
Это не измерение RTT и не обещание двукратного ускорения интернета.
[Все пять запусков](SPEEDY_BENCHMARK_2026-09-11.csv) сохранены для проверки.

Проверки покрывают независимый wire-вектор, каждый изменённый байт и усечение
кадра, разные ключи и направления, границы эпох, MTU, все размеры IPv4 от 20
до 1391 байта, обратный порядок, повторы и keepalive. Серверные тесты используют
реальные UDP-сокеты, Linux probe, повтор handshake после потери, сосуществование
трёх режимов, смену порта только после аутентификации и отзыв устройства.

Прошли 128 тестов: `cargo test --workspace --exclude mousevpn-windows-gui`.
Windows GUI исключён из запуска на Linux из-за существующего обращения к
`run_split_tunnel`, которое экспортируется только под `cfg(windows)`;
тот же конфликт присутствовал до изменений Speedy. Эти проверки не заменяют
запуск клиентов на настоящих Android, Windows или Apple устройствах.

`cargo clippy --all-targets -- -D warnings` прошёл для пакетов speedy, crypto,
config, client-wire, server, linux-platform, linux-client и linux-gui
(с префиксом `mousevpn-`).
Для изменённых пакетов также проходят `cargo fmt --check`, `git diff --check`
и проверка синтаксиса `node --check linux-gui/ui/app.js`.

## Границы маскировки

Длины и время передачи видны, тег связывает пакеты устройства внутри десяти
секунд, а одинаковые ретрансляции узнаваемы. Адрес сервера и факт зашифрованного
UDP видимы. Speedy не имитирует HTTPS и не гарантирует обход DPI, блокировки IP
или полного запрета UDP. Статические ключи маскировки не дают отдельной forward
secrecy заголовкам; содержимое защищено сессионными ключами Noise.

Это новый формат и новая композиция готовых примитивов. Испытания в памяти
не заменяют независимый криптографический анализ и проверку на целевых сетях.
