# Сборка и обновление — 5 сентября 2026

## Результат

Обновлены `myaifriend.su`, `46.8.218.43` и `138.124.249.21`. На всех трёх серверный процесс использует один проверенный бинарник:

```text
413cb76b7ac660a8091f47c71905e938019cb251aab0572bb5a0f350d5b3a212
```

Проверены SHA-256 исполняемого файла работающего процесса, состояние systemd `active`, авторизованный ответ админки 200 и отказ без токена 401. Сохранены 33, 14 и 29 устройств соответственно. Публичные адреса админки, профили, ключи, DNS, MTU и конфигурации сервисов сохранены. На каждом сервере после перезапуска зарегистрирован трафик в обе стороны через TUN; в итоговом коротком замере ошибки и потери TUN равнялись нулю. Это подтверждает работу существующих клиентов после обновления, но не измеряет выигрыш в скорости.

Старая версия бинарника и копия `/etc/mousevpn` сохранены в `/var/backups/mousevpn/2026-09-05`, доступ к каталогу только root. Обновление запускалось отдельным systemd-заданием: при неуспешной проверке оно автоматически вернуло бы старый бинарник. Откат не понадобился. Перед первой заменой предварительная проверка выявила отсутствие execute-бита у загруженного файла; права исправлены до остановки старого сервиса.

Если потребуется ручной откат только бинарника, выполнять на нужном сервере:

```sh
install -m 0755 /var/backups/mousevpn/2026-09-05/mousevpn-server /usr/local/bin/mousevpn-server.rollback
mv /usr/local/bin/mousevpn-server.rollback /usr/local/bin/mousevpn-server
systemctl restart mousevpn-server
systemctl is-active mousevpn-server
```
