# Обновление Speedy, 11 сентября 2026

По запросу владельца последовательно обновлены три действующих сервера.
Адреса, приватные ключи, административные токены и профили в этот отчёт не входят.
Сервер, обслуживавший текущее подключение владельца, обновлён последним.

На всех узлах используется один статический `x86_64-unknown-linux-musl`
бинарник сервера, собранный Rust 1.97.1 с release/thin LTO.
SHA-256: `eeef158520dc1b2c67f83625316c422b3c3fe4bd85e15d1871064c6f43db98d8`.
Он собран до последующего исправления маршрутов Linux-клиента; серверный
обработчик Speedy после развёртывания не менялся.

Перед заменой сохранены старый бинарник, конфигурация, публичный реестр
устройств, согласованная SQLite-копия истории трафика, unit службы и сетевые
настройки в `/var/backups/mousevpn/speedy-20260911/` каждого узла. Бинарник
заменялся переименованием подготовленного файла; затем перезапускалась только
`mousevpn-server.service`. На время проверки работал пятиминутный таймер
возврата прежнего бинарника. Все обновления подтверждены; возврат не потребовался,
таймеры остановлены, резервные копии сохранены.

После обновления на каждом узле подтверждены активная служба, административный
health `ok`, неизменная конфигурация и сохранение всех прежних устройств.
Содержимое правил nftables сохранилось. На node-3 перезапуск существующего unit
изменил только порядок вывода таблицы ограничения административного порта;
правила сравнены отдельно от порядка таблиц. Служба не записала ошибок уровня
error в журнал во время проверок.

## Проверка настоящих пакетов

`packet_probe` выполнялся на node-2 для node-1 и на node-1 для остальных узлов.
`ip route get` подтвердил маршрут через физический интерфейс каждого источника.
VPN владельца не участвовал в пути тестовых пакетов. Локальные TUN, маршруты
и DNS диагностический пример не изменял.

Для каждого из трёх режимов — Speedy, Legacy, Morph Balanced — проверены:

- аутентифицированный Noise-handshake и выданный MTU;
- по 10 ICMP Echo/Reply размером IP 64 байта и MTU до серверного `10.77.0.1`;
- те же пакеты до внешнего `1.1.1.1`, включая серверный TUN, forwarding и NAT;
- соответствие адресов, идентификатора, sequence, содержимого и контрольных сумм ответа.

На каждом сервере получено 120 из 120 ответов, всего 360 из 360.
Временные устройства отозваны после тестов, приватные тестовые профили удалены.
[Таблица измерений](SPEEDY_NETWORK_2026-09-11.csv) содержит все 36 серий.
Перед обновлением node-1 сам диагностический пример также проверен на прежнем
сервере в Legacy: 40 из 40 ответов.

Это короткие проверки связности и MTU. Они не измеряют пропускную способность,
длительную устойчивость или проходимость Speedy через сеть провайдера владельца.
Маршрут и нагрузка менялись между сериями, поэтому разницу RTT между режимами
нельзя считать сравнительным бенчмарком.

## Linux-клиент 0.1.11

В GUI добавлен Speedy. При обновлении серверов проявилась существующая ошибка
восстановления клиента: `File exists` при обновлении маршрута к серверу.
`RouteManager::list()` возвращал индекс и имя интерфейса, а строящийся маршрут
содержал только индекс. Равенство требовало совпадения обоих полей и ошибочно
считало существующий маршрут отсутствующим. Повторное добавление давало EEXIST
и мешало переподключению после перезапуска сервера.

Сравнение исправлено: при наличии обоих индексов сравниваются индексы; иначе
используются доступные имена. Адрес, gateway, prefix и метрика по-прежнему
должны совпадать. Регрессионный тест воспроизводит представление маршрутов,
полученное чтением реальной таблицы владельца. Чужие интерфейсы и метрики
не признаются тем же маршрутом.

Arch-сборка теперь включает новые Rust-файлы и манифесты crate до их коммита,
чтобы новый crate Speedy не терялся из локального архива исходников. Произвольные
неотслеживаемые TOML-файлы и профили в архив не добавляются.

Локально собран пакет `mousevpn-0.1.11-1-x86_64.pkg.tar.zst` и установлен
через `pacman -U` вместо `0.1.10-1`. При упаковке переиспользован release-бинарник
из рабочего дерева; содержимое всех файлов архива исходников сравнено с этим
деревом, новых зависимостей при установке не потребовалось.
SHA-256 пакета: `854af60018493923c2c927b0d54f4a41acce7938750c0e61169da586341d982f`.
Для включения нового GUI и helper нужен следующий запуск приложения.
Полное переподключение через установленный новый клиент не запускалось поверх
действующего VPN; исправление маршрута проверено регрессионным тестом.

Итоговые проверки: 128 тестов рабочего пространства прошли, кроме исключённого
на Linux Windows GUI; release/musl тесты серверного и Speedy-пакетов прошли;
clippy для изменённых Rust-пакетов, форматирование, синтаксис JavaScript и
проверка патча завершились без ошибок.
